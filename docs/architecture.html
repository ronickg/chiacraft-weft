The whole picture

Two games, two endpoints each, no server in the middle

Every game runs its own world in the same process and talks to other games directly over iroh (QUIC). A game has two network endpoints: one under the player's account key, which joins other worlds and receives link requests, and one under the open world's own key, which other players join. The services in the middle only help peers find and reach each other; anyone can run them.

Identity

One set of 24 words, four kinds of key

The words never leave the OS keychain. Everything else is derived one way from the identity key, each on its own label, so a leaked world or content key gives away nothing else. The identity key signs short statements that tie the other keys to it, which is how a world learns who owns a key it has never seen.

World addresschiacraft://w/<world key>?n=…&r=…&a=…. The key alone is enough; name, relay and direct addresses are hints. Old tickets still parse.
World certificate"chiacraft world v1": the world key, generation and creation time, signed by the owner's identity. Served in every status answer.
One world, one placeBefore hosting, the game pings its own world key. If something answers, the world is open elsewhere and hosting is refused.
Protocol 5

Joining a world downloads its packages first

Code mods must match exactly. Data packages travel: the host offers what its world plays with, the guest downloads what it lacks (after the player agrees), loads exactly that set, and proves it by hash before it is let in.

Phase 3 slice 1

Your world keeps its own content while you visit

The game and your world's server share one process. When you visit a world with other packages, the game switches to that world's content, but your server must not. So the engine asks one question every time code reads the content (or a synced setting such as a game rule): is this one of a server's threads?

Leaving for another worldIf your world is hosted, it keeps running for its guests and becomes "home". Otherwise it is saved and closed.
Coming back"Back to <world>" in the pause menu, or automatically when the world you visit goes offline or the join fails.
QuittingSave and Quit, or closing the game, stops home too.
Phase 3 slice 3

A link is one record both worlds sign

Worlds are offline most of the time, so requests go to the owner's game, which is the inbox for all of their worlds whenever it runs. Anything that can't be delivered waits in an outbox and is tried again for up to two weeks.

Phase 3 slice 4

A portal holds a link id and nothing else

The portal block lives in the game's own portals mod, so it means the same in every world whatever packages they play with. Its hidden block entity keeps one link id. Only the world's owner can choose it; the server asks the engine (through the bridge) before it changes anything.

Phase 2

A package is named by its exact files

Blocks, items, recipes and tags are TOML files with their art, and no code. The package's identity is a hash of a canonical list of every file's path, size and hash, so the same files give the same name on every computer, and a world pins exactly the version it was played with.
